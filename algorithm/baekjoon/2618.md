# 💳 문제이해

N * N개 그래프/행열이 주어집니다. 경찰자 두 대의 위치는 좌표, (1, 1) 와 (N, N)
에 있습니다. W 개의 사건의 좌표가 주어집니다.  사건은 순서대로 
처리해야 합니다. 하나의 사건은 하나의 경찰자가 필요합니다. 모든 사건을
처리하기 위해 필요한 최소 이동 횟수를 구하시오. 가중치는 모두 1입니다.

## 🚥 문제접근

그래프는 인접한 행열을 사용합니다. 가중치가 모두 같으므로 `BFS`를 
고려해 봅니다. 

두 개의 경찰자 중 어떤 사건의 어떤 경찰자가 배치되어야 하는지 중요합니다.

### 🌏 분석

- 경찰자1: (1, 1)좌표에 있는 경찰자
- 경찰자2: (N, N)좌표에 있는 경찰자

**해결 해야 할 점**:

- 사건은 순서대로 처리해야 합니다.
- 어떤 경찰자가 어떤 사건을 맡아야 할까?: 가장 가까운 경찰자.
    - 경찰자1 과2 의 범위를 절반 쪼개면 어떻습니까?
    절반을 쪼갠다 하더라도, 한 쪽에만 몰려 있으면 의미가 없습니다.

- 차 위치/현재 사건 위치부터 다음 사건 위치에 최단 거리는 간단하게 구할 수 있습니다.
    - 목표 좌표에, (y, x)를 현재 좌표에 뺀 값입니다.
    - 목표 좌표(5, 5), 현재 좌표(3, 2)
    - 최단 경로 = (5 - 3) + (5 - 2) = 5
    - 참고로 목표 좌표가 더 크면, 각 차이의 절대 값을 구하면 됩니다.

- 사건1을 경찰차1 이 처리한다고 해서 사건 2를 경찰차 2가 처리하면 효율적이라는
보장이 없습니다. 예를 드레

- 최단 거리는 간단하게 구할 수 있습니다. 그러면 어떤 경찰 찰를 어떤 사건에
보내야 효율적으로 처리할 수 있을까요?
    - 모든 경우를 비교하는 수밖에 없을 것 같습니다. `Dynammic Programming`을
    사용합니다.

#### 🥖 Brute Force(전체 탐색)

모든 경우를 탐색하는 `Brute force`를 사용하면...
1. 경찰차 1만 사용하는 경우
    - 두 번째 사건을 경찰차 2만 사용하는 경우
        - 1, 2, 1, ...
    - 세 번째 사건을 경찰차 2만 사용하는 경우
        - 1, 1, 2, 1, ...
....
2. 경찰차2 만 사용하는 경우
    - 2, 2, 2, 2
    - 두번 째 사건을 경찰차1만 사용하는 경우
    - 2, 1, 

따라서 $O(2^N)$ 걸릴 것 같습니다.

- 왜 2^N이라고 하면
- 각 사건은 두 가지 경우의 수밖에 없습니다.
    - 경찰차 1인 것이냐 경찰차 2인 것이냐
    - 해서 수학적으로 보면...
    - 2 x 2 x 2 x 2 x 2 x ... x 2 = 2^n
    - 대충 이렇습니다. 그래서 모든 경우를 탐색하면 $O(2^n)$, 지수적(exponential)
    입니다.

해당 문제의 경우 전체 탐색을 사용할 필요는 없습니다.

가령, 사건1의 위치는 경찰차 1의 바로 옆에라고 합니다. 그러면 사건1은 경찰차
1이 맡는 편이 효율적입니다. 그렇다면 다른 경우의 수에서도 사건1은 경찰차 1
아닌 경우의 수를 계산할 필요가 없습니다. 이를 위해 **동적 계획법**을 사용합니다.

#### 🪔 Dynamic Programming

- 경찰차는 두 대입니다. 그러니 각 사건의 경우의 수는 두 개입니다.
- 두 경찰차의 한 사건의 대해서 최단 경로를 저장할 필요가 있나요?

여기서 막혔습니다.

생각해보니 각 자동차를 추적해서 다음 사건과의 최단 거리를 구해 비교하면 
되지 않을까 싶습니다. 결국에는 사건에서 가장 가까운 자동차를 배치하면 
되지 않을까요?

그렇다면, 두 경찰차의 거리가 서로 같을 때는 어떻게 처리하면 됩니까?
네, 위 방식으로는 처리하기 어렵습니다. 그래서 각 최단 경로를 계산할 필요가 
있습니다.

- 0, x2, 0, 0, 1, 0, x1, 0, 0, 2

또 위 같은 경우 경찰차 1이 사건 x1의 가깝다 하더라도, 경찰차 2가 처리하는 
편이 효율 적입니다.

1. 경찰차1이 x1을 방문하는 경우
    - x1: 2번
    - x2: 5번 // 되돌아가기
    - 총합: 7번
2. 경찰차2가 x1을 방문하는 경우
    - x1: 3번
    - x2: 3번
    - 총합: 6번입니다.

위와 같이 사건과 가장 가까운 경찰 차가 우선적으로 처리하는 방식은
처리하는 사건 순서가 정해져 있기 때문에 어려울 수 있습니다.

그렇다면 어떻게 두 경우의 자동차의 각 사건의 최단 거리를 구할 수 있을까요?

## 🔍 검색

도저히 모르겠어서 결국에는 찾아 보았습니다.

`Brute Force`방식처럼 모든 경우를 탐색하는 게 맞았습니다. 다만,
중복되는 경우는 스킵하는 방식입니다.

예시: 
- 1, 1, 1
- 1, 1, 2
- 1, 2, 1
- 1, 2, 2
- 2, 1, 1
- 2, 2, 1
- 2, 2, 2
- 2, 1, 2

위와 같이 사건이 3개나 있다면, 경우의 수는 총 2^3 8가지입니다.

이 부분에서 중복을 피한 계산이라는 것이 무슨 의미인가요?

**예시**:
- 사건1: (3, 2)
- 사건2: (4, 5)
- 사건3: (2, 2)

- 경찰차1과 사건1 사이의 최단 거리 = abs(3 - 1) + abs(2 - 1) = 3
    1. 사건2 // 경찰차1이 사건1을 처리했다는 가정
        - 경찰차1과 사건2 사이의 최단 거리 = abs(4 - 3) + abs(5 - 2) = 4
            1. 사건 3 // 경찰차 1이 사건 2를 처리했다는 가정 
                - 경찰차1과 사건 3 사이의 최단 거리 = abs(2 - 4) + abs(2 - 5) = 5
                - 경찰차2와 사건 3 사이의 최단 거리 = abs(2 - 5) + abs(2 - 5) = 6
        - 경찰차2와 사건2 사이의 최단 거리 = abs(4 - 5) + abs(5 - 5) = 1
            1. 사건 3 // 경찰차 2가 사건 2를 처리했다는 가정
                - 경찰차2 와 사건3 사이의 최단 거리 = abs(2 - 4) + abs(2 - 5) = 5
                - 경찰차1 과 사건3 사이의 최단 거리 = abs(2 - 3) + abs(2 - 2) = 1
- 경찰차2과 사건1 사이의 최단 거리 = abs(3 - 5) + abs(2 - 5) = 5 
    1. 사건2 // 경찰차2가 사건 1을 처리했다는 가정
        - 경찰차2 와 사건2 사이의 최단 거리 = abs(4 - 3) + abs(5 - 3) = 4
            1. 사건 3 // 경찰차 2가 사건 2를 처리했다는 가정
                - 경찰차2 와 사건3 사이의 최단 거리 = abs(2 - 4) + abs(2 - 5) = 5
                - 경찰차1 과 사건3 사이의 최단 거리 = abs(2 - 1) + abs(2 - 1) = 2
        - 경찰차1 와 사건2 사이의 최단 거리 = abs(4 - 1) + abs(5 - 1) = 7
            1. 사건 3 // 경찰차1 이 사건 2를 처리했다는 가정
                - 경찰차1 이 사건3 사이의 최단 거리 = abs(2 - 4) - abs(2 - 5) = 5
                - 경찰차2 가 사건3 사이의 최단 거리 = abs(2 - 3) - abs(2 - 2) = 1


두 가지 경우를 비교할 때 자주 사용하는 행열을 사용해봅니다.
- 행은 경찰차 1이 처리한 사건 번호
- 열은 경찰차 2가 처리한 사건 번호

- 행열 데이터는 -1으로 초기화 시켜줍니다.

| 경찰차1 / 2 | 초기  | 사건1 | 사건2 | 사건3 |
| :---:       | :---: | :---: | :---: | :---: |
| 초기        |   5   |   6   |   2   |
| 사건 1      |   2   |   x   |   1   |
| 사건 2      |   5   |   1   |   x   |
| 사건 3      |       |       |       | 

1. 0, 0 
    1. 1, 0
        1. 2, 0: 경찰차 1이 사건2를, 경찰차 2가 초기 상태(사건을 처리하지 않음)라고 가정합니다.
            -  5 < 6 = 5입니다.
        2. 1, 2경찰차 1 = 사건1, 경찰차 2 = 사건 2
            -  5 < 1 = 1입니다.
        - 1, 0: 경찰차1 = 사건1; 경찰차2 = 초기
            - 위 조건일 때, 사건 2의 최단 경로 +  사건 3의 최단 경로
            - 1 + 1 = 2
    2. 0, 1
        1. 2, 1: 경찰차1 = 사건 2, 경찰차2 = 사건1 
            - 5 > 1 = 1
        2. 0, 2: 경찰차1 = 초기, 경찰차2 = 사건 2
            - 5 > 2 = 2
        - 0, 1: 
            - 위 가정하에
                - 사건2와의 최단 경로 경찰차1: 7
                - 사건2와의 최단 경로 경찰차2: 4
            - 다음 사건 가정
                - 2, 1의 대한 최단 경로 = 1
                - 0, 2의 대한 최단 경로 = 2
            - (7 + 1) > (4 + 2) = 6
            - 따라서 0, 1의 대한 최단 경로는 6
    - 0, 0의 대한 최단 경로
        - 경찰차1과 사건1과의 최단 경로: 3
        - 경찰차2와 사건1과의 최단 경로: 5
        - 각 경찰차가 다음 사건 처리했다고 가정
            - 미리 계산한 경찰차1이 사건1을 처리했다는 최단 경로: 1, 0 = 2
            - 이하동문, 최단 경로: 0, 1 = 6
        - (2 + 3) < (6 + 5) = 5
        - 따라서 경찰차1이 사건1을 맡는 편이 효율적입니다.

원리는 다음과 같습니다.

DP\[i]\[j]가 있습니다. i는 행, j는 열입니다.

DP\[5]\[3]는 경찰차 1이 5번째 사건을 처리했습니다. 경찰차 2가 3번째 사건을
처리했다는 것을 의미합니다. 그러면 해당 값으로는 다음 사건의 대한 최단
경로를 의미합니다.

> "경찰차1이 사건 5를 처리했습니다. 경찰차2가 사건3을 처리했습니다. 그러면
다음 사건, 사건6에 대한 최단 거리는 해당 값입니다."
그러면, DP\[i]\[j]는 어떻게 구할까요?

DP\[i]\[j]는 각 사건마다 다음 사건을 처리하기 위해 필요한 최단 거리를 
비교합니다.

다만 초반 사건부터 최단 경로를 저장하는 게 아니라 마지막 사건부터
순차적으로 사건1 번째까지의 최단 경로를 저장합니다.

즉 마지막 사건을 우선적으로 기록한 다음에 이전 사건을, 각 경찰차마다
어떤 사건을 가정하여 처리합니다.
